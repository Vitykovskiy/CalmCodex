# Подготовка промпта для Codex

Режим `prompt` превращает черновик в краткую постановку задачи. Режим `rewrite` убирает эмоциональный шум и сохраняет тип реплики. При отключённом Ultracave ясные нейтральные реплики в режиме `rewrite` возвращаются дословно.

В VS Code выберите **Подготовить промпт для Codex** в контекстном меню поля ввода. Для автоматической подготовки перед отправкой задайте `calmCodex.mode = prompt`; автоматическая обработка включается параметром `calmCodex.rewriteOnSend`. По умолчанию выбран `rewrite`. Ручные команды выбирают свой режим независимо от настройки автоматической обработки. В меню служб macOS доступна команда с тем же названием. Для CLI используйте `CalmCodex --stdin --mode prompt`; прежний вызов `CalmCodex --stdin` использует редактор.

## Что меняется

Подготовка выделяет цель, релевантный контекст, ограничения и описанный пользователем результат. Структура соразмерна запросу: короткому поручению достаточно предложения; составной задаче может помочь список. Уже достаточный запрос не расширяется ради формата.

Вопрос остаётся запросом сведений, план — планом, наблюдение — наблюдением. Режим не придумывает отсутствующие технические подробности, причины ошибки или продуктовые требования. Он сохраняет указанные проверки, но не превращает каждый запрос в обязательный аудит, тестовую кампанию или публикацию. Реализацию и выбор средств проверки определяет исполняющий Codex в контексте проекта.

Модель получает редактируемый `draft` с защищёнными фрагментами. При обработке сообщения по частям она также получает `context.before` и `context.after`: текст остальных частей в их порядке. Цитаты, пути и код маскируются во всех этих полях одним механизмом; их содержимое остаётся локальным. Контекстные литералы получают отдельные метки, которые отклоняются при восстановлении ответа.

Контекст помогает распознать риторический вопрос и однозначный предмет отсылки. Поручения, способы действия, условия и самостоятельные вопросы берутся только из `draft`. Например, соседнее «Добавь макет карточки. Код не меняй» позволяет понять «Я должен догадаться, как это выглядит?» как «Покажи, как это выглядит»; повторять соседние поручения в ответе на этот фрагмент не нужно. При работе с выделением контекст ограничен выделенным текстом.

Перед заменой редактор отклоняет буквальный перенос целых соседних фраз, которых нет в целевом тексте. Исходный черновик при этом сохраняется целиком. Эта проверка не определяет семантическое равенство разных формулировок; такие ошибки проверяются отдельно на ответах модели и на собранном сообщении.

История переписки, содержимое проекта и изображения модели недоступны. Отсылки разрешаются только по явно указанному тексту сообщения. Самоисправление с метками сохраняется вместе со словами отмены; буквальная сохранность важнее перестройки предложения. Изменение порядка меток или склеивание отдельного блока с соседним текстом отклоняется до замены черновика. Для отдельной строки с меткой исходные отступы и хвостовые пробелы восстанавливаются кодом, даже если модель их изменила.

В VS Code режим `prompt` объединяет соседние обычные абзацы полного черновика в один блок. Поэтому поручение из последнего абзаца можно перенести в начало, а связанные гипотезы и вопросы собрать рядом. «Наверное», «может» и просьба оценить решение сохраняют предположительный смысл: предложенный реестр шаблонов не становится утверждённым требованием.

Вложения, код, форматирование и сложная структура документа ограничивают перестройку. Такие участки сохраняют прежние диапазоны и метки; соседний текст используется для понимания. При частичном выделении также сохраняется адресная замена без перестройки абзацев. Одновременно обрабатываются до трёх блоков; общий срок ограничен 70 секундами. Блок из одного речевого шума можно убрать, если в остальных блоках есть текст. Сбой модели или полностью пустой результат сохраняет исходный черновик.

Такой черновик требует нескольких вызовов модели; в каждом повторяется соседний текст. Это увеличивает расход токенов и может увеличить задержку. Обычная цельная реплика требует одного вызова. Режим `rewrite` сохраняет прежний способ обработки целого текста.

Пример предполагаемого преобразования, а не результат измерения модели:

> API не меняй. Сейчас одно нажатие создаёт три копии. Исправь это, нужна одна копия на нажатие.

> Исправь сохранение: сейчас одно нажатие создаёт три копии, должна создаваться одна. API не меняй.

Риторическое «Я должен фантазировать, как это выглядит?» после замечания об отсутствующем макете выражает потребность увидеть результат. Оно не поручает агенту перестать фантазировать. Настоящий вопрос «Можно фантазировать при разработке эскиза или нужно точно повторять макет?» сохраняет вопросительную форму. Одна и та же лексика требует разных решений по смыслу всего сообщения.

## Сжатие Ultracave

`calmCodex.ultracave` включает дополнительное сжатие в обоих режимах; по умолчанию оно включено. После определения смысла модель сокращает повторы, вводные и избыточные связки в том же запросе. Вопросы, предположения, ограничения, порядок действий и буквальные фрагменты имеют приоритет перед краткостью. Жёсткого ограничения длины нет.

Отключите настройку, чтобы оставить обычную обработку выбранного режима. Для службы macOS используется `defaults write local.calmcodex.service ultracave -bool false`; для одного вызова CLI — `--no-ultracave`. Флаг `--ultracave` включает сжатие для одного вызова независимо от настройки службы. Переключатель VS Code имеет приоритет перед настройкой службы.

## Модель и уровень рассуждений

По умолчанию используются `gpt-6-luna` и `medium`. Настройки `calmCodex.model` и `calmCodex.reasoningEffort` относятся к переписчику, независимо от модели в основном чате Codex. Пустое значение наследует настройку службы macOS. Приоритет: параметры конкретного вызова из VS Code или CLI → настройки `local.calmcodex.service` → значения по умолчанию. [Настройка модели и CLI](installation.md#выбор-модели-и-cli).

Для обработки отдельного фрагмента вместе с контекстом CLI принимает `--stdin-json --mode prompt`. В стандартный ввод передаётся JSON:

```json
{
  "draft": "Я фантазировать должен, как это выглядит?",
  "context": {
    "before": ["Снова нет макетов. Добавь к элементу фрагмент макета."],
    "after": ["Код пока не меняй."]
  }
}
```

В стандартный вывод возвращается только переработанный `draft`. `--allow-empty` разрешает пустой результат отдельной части в режиме `prompt`; расширение проверяет, что в остальных частях остался содержательный текст.

При обновлении правил заново проверьте применимость источников, измените `macos/Resources/prompt.txt` и дату сверки. Сравнивайте сохранение намерения и качество выполнения задач, а не длину или внешнюю сложность формулировки. Изменение промпта не обновляет модель автоматически.

## Проверка

Проверки расширения покрывают выбор режима и обработку ошибок. Swift-проверки покрывают параметры CLI и сохранность литералов. Они не измеряют семантическую точность модели.

Для проверки с установленной Luna используйте отдельные новые реплики и несколько повторов. Обязательные группы: настоящий вопрос с объяснением цели ответа; явный запрос исправления; просьба только о плане; наблюдение без поручения; ограничения; самоисправления с кодом и файлами; переносное и буквальное употребление спорных выражений. Примеры из самого промпта проверяют регрессию, но не заменяют независимый набор.

Регрессии риторических вопросов запускаются командой `npm run test:live:rhetoric` после сборки. Набор проверяет оба режима, полный черновик и фрагмент с соседним контекстом, настоящие и смешанные вопросы. `CALMCODEX_TEST_BINARY` или `CALMCODEX_ENGINE` задаёт путь к текущей сборке. Для сравнения моделей на одном наборе:

```sh
CALMCODEX_TEST_MODEL=gpt-6-luna CALMCODEX_TEST_REASONING_EFFORT=medium npm run test:live:rhetoric
CALMCODEX_TEST_MODEL=gpt-6.2-sol CALMCODEX_TEST_REASONING_EFFORT=medium npm run test:live:rhetoric
```

Ответы выводятся для ручной проверки смысла. Автоматические проверки ловят отдельные ошибки, но сами по себе не доказывают превосходство модели. Оценивайте сохранение намерения, добавленные поручения и задержку на новых репликах, которые не использовались для настройки промпта. Вызовы расходуют лимит аккаунта Codex.

`npm run test:context` проверяет полную цепочку редактора и обработчика с заданным ответом движка: результат с поручениями из соседнего блока отменяет отправку, а корректный результат применяется без дублей и с сохранением вложений. Для той же цепочки с настоящим движком после сборки запустите `npm run test:live:context`. По умолчанию используются Luna/medium, Ultracave включён и три повтора; путь и модель задаются теми же переменными окружения. Отмена замены защищает черновик, но считается провалом проверки качества модели.

Регрессии вопроса об аудитории запускаются на текущей сборке командой `npm run test:live:prompt` после `zsh macos/build.command`. При необходимости задайте путь к собранному движку через `CALMCODEX_ENGINE`. По умолчанию выполняются три независимых вызова для каждого из четырёх случаев; `CALMCODEX_LIVE_REPETITIONS` принимает значение от 1 до 10. Проверяются исходный вопрос из ревью, другая формулировка вопроса, настоящее поручение изменить обложку и известный риторический упрёк. В выводе сохраняются ответы для проверки смысла. Эти проверки выявляют конкретные регрессии, но не заменяют семантическую оценку и независимый набор.

Критерий сохранения намерения: все исходные требования, вопросы, условия и буквальные фрагменты сохранены; новых действий и фактов не появилось. Проверку качества исполнения отделяйте от проверки самого переписывания: одинаковые задачи передавайте Codex с исходным и подготовленным запросом при одинаковом контексте проекта.
